# BTC LLM Council — Agent Enhancement Specification (v2)

## Overview

v2 addresses two structural defects exposed by backtesting: the sentiment and fundamental agents are **blindfolded in historical simulation** (they receive neutral stubs instead of real data), and the deliberation **consensus thresholds are mathematically unreachable** when two of three directional agents have no signal to work with.

The result: a Jan–Aug 2023 backtest (`tmp/20260421_033621/`) produced 100% HOLD signals while BTC rallied 64% (16.6k → 27.3k). Agent logs confirm:

| Agent | Avg confidence | Root cause |
|---|---|---|
| Technical | 45 | OHLCV-only view; reads a ranging regime during a trend |
| Sentiment | 25 | `NEUTRAL_NEWS_STUB` — no historical news source |
| Fundamental | 45 | `NEUTRAL_ONCHAIN_STUB` — SOPR = 1.0, flows = 0, no macro |
| Risk Manager | n/a | 0 vetoes — not the bottleneck |
| Deliberation | — | Avg 38.3 < 60 threshold → HOLD every cycle |

**v2 theme:** Give the agents real historical inputs, then replace the brittle consensus gate with a confidence-weighted signed-score that allows partial-conviction trades.

**Design principles (inherited from v0/v1):**
- Walk-forward only — no future data influences a past decision
- Look-ahead is prevented at the data-slicing layer, not assumed
- Prompts frozen for any given backtest window (no in-flight tuning to avoid overfitting)
- Long-only: SELL = close-to-cash only

---

## Framework

| Component | Tool |
|---|---|
| Historical news | GDELT DOC 2.0 `artlist` API (free, no key, ~2015–present) |
| Historical on-chain | CoinMetrics Community API (free, no key, daily BTC metrics) |
| Macro data | yfinance (DXY, VIX, S&P 500, 10Y yield — already a dependency) |
| Decision logic | Deterministic Python scoring function (LLM narrates, code decides) |
| All other components | Unchanged from v1 |

**Cost:** Negligible marginal cost — all new data sources are free. Anthropic API cost unchanged (~$10–15/year/backtest).

### Phase 2.5 — Decision-logic rework (data-independent)

**Goal:** Replace the hard 60/70 consensus thresholds with a confidence-weighted signed-score. This is data-independent and can be implemented and tested before Phases 1–2 are fully wired.

#### Scoring formula

```python
def compute_signed_score(outputs: CouncilOutputs) -> tuple[str, float]:
    """Compute a confidence-weighted directional score from agent outputs.

    Returns (final_signal, score).

    Each directional agent contributes:
      sign(direction) × confidence/100 × weight
    Agents with confidence < 30 are excluded (confidence floor — low-confidence
    neutrals should abstain, not dilute the score toward zero).

    Score ∈ [-1.0, +1.0]:
      ≥ +0.25  → BUY,  size = min(20%, 20% × score)
      ≤ -0.25  → SELL
      else     → HOLD

    Risk veto (outputs.risk.veto = True) always overrides to HOLD regardless of score.
    """
    WEIGHTS = {"technical": 0.40, "sentiment": 0.25, "fundamental": 0.35}
    CONF_FLOOR = 30
    TRADE_THRESHOLD = 0.25

    sign = {"BUY": 1, "SELL": -1, "HOLD": 0}
    agents = {
        "technical":   (outputs.technical.direction,   outputs.technical.confidence),
        "sentiment":   (outputs.sentiment.direction,   outputs.sentiment.confidence),
        "fundamental": (outputs.fundamental.direction, outputs.fundamental.confidence),
    }

    weighted_sum = 0.0
    weight_sum = 0.0
    for name, (direction, conf) in agents.items():
        if conf < CONF_FLOOR:
            continue
        w = WEIGHTS[name]
        weighted_sum += w * sign[direction] * conf / 100
        weight_sum += w * (conf / 100)

    score = weighted_sum / weight_sum if weight_sum > 0 else 0.0

    if outputs.risk.veto:
        return "HOLD", 0.0
    if score >= TRADE_THRESHOLD:
        return "BUY", score
    if score <= -TRADE_THRESHOLD:
        return "SELL", score
    return "HOLD", score
```

Position size derived from score magnitude: `size_pct = min(20.0, 20.0 * abs(score))`.

The deliberation LLM still runs and produces `consensus_summary` and `key_disagreements` (narrative). Its `final_signal` output is **overridden** by `compute_signed_score`. The `score` field is added to `DeliberationOutput` for logging and analysis.

### Phase 3 — Macro context via yfinance

**Goal:** Give the fundamental agent a structured macro backdrop so it can distinguish a bull trend in a risk-on environment from one during risk-off conditions.

**Source:** yfinance tickers already a dependency. Note: `^TNX` (10Y yield) is quoted ×10 — divide by 10 before use.

**Macro bias rule:**

| Condition | Bias |
|---|---|
| VIX < 20 AND DXY 20d trend declining AND SPX 20d trend rising | risk-on |
| VIX > 25 OR DXY 20d trend rising strongly (+1% in 20d) | risk-off |
| Else | neutral |

#### `src/data/macro.py`

```python
class MacroData(BaseModel):
    vix: float
    dxy: float
    spx_20d_change_pct: float
    tnx_yield_pct: float     # ^TNX divided by 10
    macro_bias: MacroBias    # risk-on | risk-off | neutral

def fetch_macro_for_date(as_of: datetime) -> MacroData:
    """Fetch DXY, VIX, SPX, TNX from yfinance for a given date.

    Uses slice date < as_of.date() to avoid look-ahead.
    ^DXY has spotty yfinance coverage pre-2020; FRED DTWEXBGS used as fallback.
    ^TNX is quoted ×10 — divided internally.
    Falls back to macro_bias=neutral on any fetch error.
    """
```

#### `src/models.py`
- Add `MacroData` model (fields above).
- Add `macro: MacroData | None = None` to `MarketContext`.

#### `src/data/assembler.py`

#### `prompts/fundamental_analyst_v2.txt`
- Add an explicit macro block showing `vix`, `dxy`, `macro_bias`.
- Instruct the agent: use macro context to weight on-chain signals (accumulation in risk-on is more bullish than in risk-off).
- Instruct full 0–100 confidence range usage.

- `macro_bias` computed correctly for known historical VIX/DXY values

**Deliverable:** Fundamental agent can reason about macro regime, raising confidence on aligned setups.

### Phase 5 — Validation

**Goal:** Verify v2 unblocks the all-HOLD problem and meets success targets. Strict walk-forward hygiene.

#### Tuning window: Jan–Dec 2022 (bear market + ranging)

```bash
python -m src.backtest.engine --start 2022-01-01 --end 2023-01-01 --capital 250000
```

Sweep over:
- `TRADE_THRESHOLD` ∈ {0.15, 0.20, 0.25, 0.30}
- `CONF_FLOOR` ∈ {20, 30, 40}

Accept the configuration where: Sharpe ≥ 1.0, trades ≥ 10, max drawdown < 25%.

#### Holdout window: Jan–Aug 2023 (the original all-HOLD window)

Run **once** with the tuned config. No further parameter changes after this run.

```bash
python -m src.backtest.engine --start 2023-01-01 --end 2023-09-01 --capital 250000
```

#### Acceptance criteria

| Metric | Target |
|---|---|
| Signal distribution | Not all-HOLD (≥ 5 BUY or SELL signals) |
| Sharpe ratio | ≥ 1.5 |
| Max drawdown | < 20% |
| Expectancy | Positive (any positive USD/trade) |
| Council consistency | ≥ 40% unanimous cycles |

If acceptance criteria are not met, document the shortfall in this spec file and propose v2.1 follow-up changes. **Do not re-tune using the 2023 holdout window.**

#### Inspect agent logs

After each run, check `tmp/YYYYMMDD_HHMMSS/agents/*.json`:
- Sentiment agent confidence distribution should span > 25 (should see values 40–80).
- Fundamental agent confidence distribution should see values > 45 on clear on-chain moves.
- Technical agent should show confidence > 60 during the 2023 uptrend.

## Look-Ahead & Robustness Rules

These must be enforced in code and documented in comments:

- **GDELT:** Query with `end_datetime = as_of - timedelta(hours=24)`. Never `<= as_of`.
- **CoinMetrics:** Slice `date < as_of.date()`. Metrics are timestamped at close; the as_of day's close has not yet occurred.
- **Fear & Greed:** Existing `max(earlier_date)` lookup is correct — keep.
- **yfinance macro:** Slice `date < as_of.date()` (same rule as CoinMetrics).
- **`^TNX` quirk:** Raw value is ×10 (e.g., `39.7` = 3.97% yield). Divide by 10. Document in `macro.py`.
- **Threshold tuning:** Tune only on the 2022 window. Never re-tune after observing the 2023 holdout.
- **Macro regime:** Do not tune `macro_bias` thresholds on the validation window. The VIX/DXY thresholds are set from prior literature, not from backtest performance.
- **GDELT allowlist:** Verify source coverage ≥ 5 items/day on the 2022 tuning window before running the 2023 holdout. Adjust `min_count` floor if needed.
