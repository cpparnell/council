# Council Framework — Strategy Generalisation Specification (v3)

## Overview

v3 generalises Council from a single hardcoded strategy into a **config-driven framework**. A user defines a strategy entirely in a single YAML file — naming their own agents, providing prompt files, assigning weights, and specifying risk rules. No Python code needs to be written or modified. The existing technical/sentiment/fundamental/risk council becomes the reference implementation (`strategies/default.yaml`).

**Design goals:**
- Zero-code strategy creation: one YAML file + one or more prompt text files
- Same strategy file works for both backtest and paper trading (mode is a flag, not a schema difference)
- Scoring, veto logic, and SL/TP are fully derived from the config
- Existing tests and backtest engine are unaffected

---

## Strategy Config Format

A strategy is a single YAML file. Example:

```yaml
# strategies/default.yaml  — migrated equivalent of the current v2 council
name: "BTC Council v2"
version: "2"

agents:
  - name: technical
    model: claude-haiku-4-5
    prompt: prompts/technical_analyst_v2.txt
    weight: 0.40

  - name: sentiment
    model: claude-haiku-4-5
    prompt: prompts/sentiment_analyst_v2.txt
    weight: 0.25

  - name: fundamental
    model: claude-haiku-4-5
    prompt: prompts/fundamental_analyst_v2.txt
    weight: 0.35

  - name: risk
    model: claude-sonnet-4-6
    prompt: prompts/risk_manager_v2.txt
    is_veto: true          # if this agent outputs veto=true, force HOLD

deliberation:
  enabled: true
  model: claude-sonnet-4-6
  prompt: prompts/deliberation_v2.txt

scoring:
  confidence_floor: 30     # agents below this confidence abstain from score
  trade_threshold: 0.25    # |score| must exceed this to trade

risk:
  stop_loss:
    type: atr_multiple     # atr_multiple | fixed_pct | none
    value: 2.0             # 2× ATR-14 below entry
  take_profit:
    type: fixed_pct
    value: 0.06            # 6% above entry
  max_position_pct: 20.0   # max % of portfolio in a single position

validation:
  max_drawdown_pct: 15.0        # halt cycle if portfolio drawdown exceeds this
  atr_spike_multiplier: 2.0     # halt if ATR-14 > value × 30-candle ATR avg
  min_news_count: 5             # soft warning threshold (does not halt)
```

**Constraints:**
- `agents` must have at least 1 entry
- `weight` values across non-veto agents must sum to 1.0 (loader validates and raises on violation)
- At most one agent may have `is_veto: true`
- `deliberation` is optional (if omitted, no narrative agent runs — scoring is purely deterministic)
- Prompt paths are resolved relative to the project root

**SL/TP rule types:**

| Type | `value` meaning |
|---|---|
| `atr_multiple` | `value` × ATR-14 below/above entry price |
| `fixed_pct` | `value` as a percentage (e.g. `0.05` = 5%) |
| `none` | No SL or TP placed |

## Agent Output Schema

All user-defined agents must produce a single standard JSON output. This eliminates agent-specific Pydantic models and makes the runner fully generic.

**Non-veto agents** → `GenericAgentOutput`:
```python
class GenericAgentOutput(BaseModel):
    direction: Direction      # BUY | SELL | HOLD
    confidence: int           # 0–100
    reasoning: str            # free-form explanation (used by deliberation agent)
```

**Veto agent** → `VetoAgentOutput`:
```python
class VetoAgentOutput(BaseModel):
    veto: bool
    veto_reason: str | None
    reasoning: str
```

The system prompt for each agent tells it which schema to return. The framework injects the structured output tool definition automatically (identical to `call_agent` today). Users don't need to define schemas in their prompts — just instruct the agent on what to reason about and how to set `direction` and `confidence`.

## Architecture

```
strategy.yaml
    │
    ▼
StrategyLoader.load(path)  →  StrategyConfig (validated Pydantic model)
    │
    ▼
render_context_block(ctx)  →  str (same for all agents)
    │
    ▼
run_strategy_council(ctx, config, client)
    ├─ [parallel] for each non-veto agent: call_generic_agent()  →  GenericAgentOutput
    ├─ [parallel] veto agent (if any):     call_veto_agent()     →  VetoAgentOutput
    │
    ├─ if veto.veto → return HOLD immediately (skip deliberation)
    │
    ├─ compute_generic_score(outputs, config) → (signal, score)
    │
    ├─ [optional] run_deliberation_agent(outputs, config) → narrative str
    │
    └─ return GenericCouncilResult

compute_sl_tp(config.risk, ctx) → (sl_price, tp_price)
    │
    └─ feeds into execution layer (unchanged)
```

## Development Phases

### Phase 1 — Strategy config model + loader

**Goal:** Define the config schema and write a loader that validates a YAML file into a typed `StrategyConfig`.

**New file:** `src/strategies/config.py`

```python
from pydantic import BaseModel, model_validator

class AgentConfig(BaseModel):
    name: str
    model: str
    prompt: str          # relative path to prompt file
    weight: float = 0.0  # ignored for veto agents
    is_veto: bool = False

class DeliberationConfig(BaseModel):
    enabled: bool = True
    model: str = "claude-sonnet-4-6"
    prompt: str

class SLTPRule(BaseModel):
    type: Literal["atr_multiple", "fixed_pct", "none"]
    value: float = 0.0

class RiskRules(BaseModel):
    stop_loss: SLTPRule
    take_profit: SLTPRule
    max_position_pct: float = 20.0

class ScoringConfig(BaseModel):
    confidence_floor: int = 30
    trade_threshold: float = 0.25

class StrategyConfig(BaseModel):
    name: str
    version: str = "1"
    agents: list[AgentConfig]
    deliberation: DeliberationConfig | None = None
    scoring: ScoringConfig = ScoringConfig()
    risk: RiskRules

    @model_validator(mode="after")
    def validate_weights(self) -> "StrategyConfig":
        """Non-veto agent weights must sum to 1.0 (±0.001 tolerance)."""
        ...

    @property
    def directional_agents(self) -> list[AgentConfig]:
        return [a for a in self.agents if not a.is_veto]

    @property
    def veto_agent(self) -> AgentConfig | None:
        return next((a for a in self.agents if a.is_veto), None)
```

**New file:** `src/strategies/loader.py`

```python
def load_strategy(path: str | Path) -> StrategyConfig:
    """Load and validate a strategy YAML file.

    Resolves prompt paths relative to project root.
    Raises ValueError with a descriptive message on validation failure.
    """
```

**Tests:** `tests/test_strategy_loader.py`
- Valid config loads without error
- Missing required field raises `ValidationError`
- Weights not summing to 1.0 raises `ValueError`
- More than one `is_veto: true` agent raises `ValueError`
- Prompt path that does not exist raises `ValueError`
- No `is_veto` agent is valid (purely directional council)

### Phase 2 — Generic agent runner

**Goal:** Replace hardcoded agent imports in `runner.py` with a loop over `StrategyConfig.agents`.

**New models in `src/models.py`:**
```python
class GenericAgentOutput(BaseModel):

    reasoning: str

    veto_reason: str | None = None

class GenericCouncilOutputs(BaseModel):
    """Keyed by agent name from config."""
    directional: dict[str, GenericAgentOutput]
    veto: VetoAgentOutput | None = None

class GenericDeliberationOutput(BaseModel):
    narrative: str
    final_signal: Direction
    score: float = 0.0
```

**New file:** `src/strategies/context.py`

```python
def render_context_block(ctx: MarketContext) -> str:
    """Render the full MarketContext as the standard text block sent to all agents."""
```

**New file:** `src/strategies/runner.py`

```python
async def run_strategy_council(
    ctx: MarketContext,
    config: StrategyConfig,
    client: anthropic.AsyncAnthropic | None = None,
) -> GenericCouncilResult:
    """Generic council runner driven by StrategyConfig.

    1. Render the context block once.
    2. Run all agents in parallel (asyncio.gather).
    3. If veto agent exists and returns veto=True, short-circuit to HOLD.
    4. compute_generic_score(outputs, config) → (signal, score)
    5. Optionally run deliberation agent.
    6. compute_sl_tp(config.risk, ctx) → (sl_price, tp_price)
    7. Return GenericCouncilResult.
    """
```

**Old `src/agents/runner.py` is kept unchanged** — it runs the default strategy by constructing a `StrategyConfig` from `strategies/default.yaml`. This maintains full backward compatibility with all existing tests.

**Tests:** `tests/test_strategy_runner.py`
- All agents are called with the same context block string
- Veto=True short-circuits to HOLD without calling deliberation
- All-HOLD agents → HOLD result
- Parallel execution: `asyncio.gather` called once (mocked)
- Missing veto agent: no short-circuit path taken

### Phase 3 — Generic scoring and SL/TP rules

**Goal:** Replace hardcoded `WEIGHTS` dict in `scoring.py` with config-driven equivalent.

**New function in `src/strategies/scoring.py`:**

```python
def compute_generic_score(
    outputs: GenericCouncilOutputs,
    config: StrategyConfig,
) -> tuple[str, float]:
    """Config-driven version of compute_signed_score.

    Reads weights and thresholds from StrategyConfig.
    Agent weights are normalised at call time to guard against floating-point drift.
    Confidence floor and trade threshold come from config.scoring.
    Veto is evaluated before calling this function (in runner).
    """
```

**New file:** `src/strategies/risk_rules.py`

```python
def compute_sl_tp(
    rules: RiskRules,
    ctx: MarketContext,
    entry_price: float,
) -> tuple[float, float]:
    """Compute stop-loss and take-profit prices from config rules.

    atr_multiple: sl = entry - (value × ATR-14), tp = entry + (value × ATR-14)
    fixed_pct:    sl = entry × (1 - value),       tp = entry × (1 + value)
    none:         returns (0.0, 0.0) — execution layer skips SL/TP placement

    SL is always clamped to > 0.
    """
```

**Old `src/agents/scoring.py` kept unchanged** — still used by the legacy `run_council` path.

**Tests:** `tests/test_strategy_scoring.py`
- All-BUY agents with equal weights → positive score, BUY signal
- Below confidence floor: agent excluded from score
- Weighted score with mixed directions matches manual calculation
- `compute_sl_tp` with `atr_multiple`: sl < entry, tp > entry
- `compute_sl_tp` with `fixed_pct`: correct percentage offsets
- `compute_sl_tp` with `none`: returns `(0.0, 0.0)`
- Score below threshold → HOLD

## Transition Complexity Assessment

The current codebase is well-structured for this generalisation. The main seams:

| Hardcoded coupling today | v3 replacement |
|---|---|
| `runner.py` imports 4 named agent modules | Generic loop over `config.agents` |
| `scoring.py` `WEIGHTS = {"technical": 0.40, ...}` | Read from `config.scoring` |
| `CouncilOutputs` has fixed fields per agent | `GenericCouncilOutputs.directional: dict[str, ...]` |
| `AgentWeights` model has fixed agent names | `dict[str, float]` in generic deliberation |
| SL/TP from `RiskManagerOutput` fields | `compute_sl_tp(config.risk, ctx)` |
| `_build_user_message` per agent | `render_context_block(ctx)` shared |

The legacy path (`run_council`) stays untouched. The new path (`run_strategy_council`) is additive. The existing ~200 tests require no changes.

Estimated effort: ~4–5 days of focused implementation.
